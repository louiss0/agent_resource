# Native Agent parent configuration contracts

Research resolution for [issue #19](https://github.com/louiss0/agent_resource/issues/19). Retrieved **2026-10-23 UTC**. Scope: local Claude Code and Codex parent permissions/sandbox/approval, model/provider/defaults, and MCP registration. Supplements the [native Agent research at its immutable commit](https://github.com/louiss0/agent_resource/blob/686ed76939871fdf814ec00aac4de4ea05efd14c/docs/research/claude-codex-agents.md), rather than repeating Agent schemas.

## Evidence and authorization boundary

**D = live official documentation**, not an immutable release specification. All native configuration claims below are D unless otherwise labeled. **P = pinned prior research/source observation**, not independently re-audited source here. **I = inference**, not product policy. **U = unknown/not established** in this bounded pass. Immutable facts are the publication commit, prior research pin, and downloaded-response hashes in the ledger—not release-certified runtime behavior. No new source-only schema claims are made.

No web/search tool was available. Retrieval used direct HTTPS (`urllib` and `curl`, redirects followed); Claude initially returned 403 to urllib and succeeded with curl's `Mozilla/5.0` user agent. No real user configuration, credentials or environment values were read. No packages, harnesses, Agents, helpers or MCP servers were installed/executed; no behavior probes were run.

**Human-established boundary, not a research choice:** first release permits deliberate changes to these parent families **only through explicit reviewed configuration-change plans and only eligible user/project writes**. Managed/system/session-enforced authority remains inspect-only. Editing an Agent must never implicitly edit parent permissions, provider, MCP or defaults. A supported native setting is evidence for a plan, not authorization to write it.

## 4. Secrets, references and effects

| Mechanism | Verified contract and limits |
| --- | --- |
| Claude credentials | `env` is plaintext and inherited by subprocesses, **not** a vault or interpolation engine. `apiKeyHelper`: shell-command string returning model API credential, cached (five minutes default/configurable TTL), refreshed on applicable auth failures/JWT expiry. Interactive project/local helpers wait for trust. A helper declaration is execution-bearing. OAuth/provider credential chains are separate, not registration fields. [C2: env/apiKeyHelper][C12] |
| Claude MCP references | `.mcp.json` supports `${VAR}` / `${VAR:-default}` in command, args, env, URL, headers. Missing-without-default currently warns and leaves literal text—not guaranteed fail-closed rejection. Certain native/cloud credential variables resolve empty in remote URL/headers to prevent forwarding. Do not promise this interpolation for ordinary settings/arbitrary state. `headersHelper` generates JSON string-valued headers; repository/plugin helpers have credential scrubbing/trust distinctions. OAuth login is separate; no token migration implied. [C3: Environment variable expansion/headersHelper/Which variables a helper can read] |
| Codex provider auth | `env_key` names credential variable; `env_http_headers` maps header names to variable names. ### Relative references

- **Claude Read/Edit:** `//path` absolute; `~/path` home; `/path` settings-source anchored; bare/`./path` cwd-relative. Source anchor: primary working directory for project/local, personal config directory for user, file parent for `--settings`. A single slash is **not absolute**. [C5: Read and Edit]
- **Claude sandbox paths:** `/path` absolute, `~/` home, bare/`./` project/primary directory for project/local or personal config directory for user. Different from rule syntax; platform glob limits apply. [C2: Sandbox path prefixes][C1: local-file path anchoring]
- **Claude MCP `headersHelper`:** project `.mcp.json`/local → declaring project; user → config directory; project Agent inline/CLI/SDK → primary working directory; outside-project Agent → config directory. These are helper cwd rules, **not proof all stdio arguments share that base**. `CLAUDE_PROJECT_DIR` is injected into spawned servers, not necessarily available for config interpolation (`${CLAUDE_PROJECT_DIR:-.}` fallback documented). **U:** universal parent stdio executable/argument resolution not established. [C3: Where the helper runs/stdio environment]
- **Codex:** project path-valued config keys resolve from containing `.codex/`, e.g. `model_instructions_file`; legacy `agents.name.config_file` explicitly from declaring file. MCP `cwd` is process working directory; **U:** omitted/relative cwd, executable lookup and argument interpretation across user/profile/remote layers not pinned. Arbitrary argument strings are not necessarily paths. [O2: Project config][O3]
- **Codex beta profiles:** filesystem keys support absolute/home paths and symbolic roots such as `:workspace_roots`; scoped subpaths are descendants without `.`/`..` components (special `.` selects base). Not generic relative-file syntax. [O7: Filesystem paths]

### Reload/runtime caveats

**Claude D:** settings watched; most permission/hook/credential-helper edits apply live and may invoke existing `ConfigChange` hooks. `model`, `effortLevel`, `modelSettings` are start-time settings; `/model`/`/effort` changes are distinct runtime actions. New-file detection/managed delivery have exceptions. A write is **not necessarily inert until restart**. Generic external `.mcp.json`/`.claude.json` hot reload is **U** here; plugin reload docs do not establish ordinary-file reload. [C1: When edits take effect][C3: Plugin lifecycle]

**Codex U/D:** stable generic config/MCP/Agent-file hot reload not established. CLI/IDE/app and existing child threads may differ. Config must be re-resolved under trust/profile/requirements; `/permissions` runtime action is not proof of a watcher. Do not promise restart alone migrates existing threads/credentials. Sandbox enforcement remains platform/runtime dependent; beta profiles require version-scoped interpretation. [O1][O4][O7][O8][P1: lifecycle unknowns]

**I:** reviewed plans need to separate mutation, next-session interpretation, running-session side effects and effective inherited authority. Syntax/reference inspection cannot certify connectivity, credentials, enforcement or installed-version support.

## 5. Open decisions and bounded unknowns

No product policy selected. Decisions still needed:

1. Supported native version/surface profiles, including Codex beta versus legacy permissions, separate profile files, Claude local placement and host routing.
2. Reviewed-plan target identity/redaction/backup/concurrency/rollback and higher-authority diagnostics, especially mixed sensitive `.claude.json` state and cross-project changes.
3. Representation of inherited/merged/shadowed/unknown settings; deletion exposing lower layers; effects on already-running harnesses.
4. Scope-copy/reference rewriting and unsupported/lossy conversion choices. Codex provider edits cannot be project-local; native env-reference mechanisms differ.

Residual **U**: complete optional schemas/coercions/unknown-key handling; every nested Codex merge/deletion edge; relocated Claude global-state filename; universal MCP executable/path resolution; all auth-store layouts; exact release minimums for all live fields; generic reload/in-flight-child behavior; every host/managed/platform enforcement combination. These limit the evidence, not permission to guess. Later exact-version work should resolve the paths a selected workflow needs. No OS audit or whole-harness security certification.
