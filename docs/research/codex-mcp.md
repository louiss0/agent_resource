# Codex MCP registration contracts

Research for [issue 98](https://github.com/louiss0/agent_resource/issues/98). Sources are OpenAI's current documentation, consulted 2026-07-17; this is documentation research, not a runtime compatibility test. Codex and its documentation can change independently of installed versions. This concerns Codex as an MCP client, not its separate MCP server mode.

## Locations and precedence

- Codex uses TOML tables `[mcp_servers.<server-name>]` in `~/.codex/config.toml` or project `.codex/config.toml`. CLI and IDE share configuration. `$CODEX_HOME` can relocate the user configuration directory (default `~/.codex`). [MCP guide](https://developers.openai.com/codex/mcp/), [configuration basics](https://developers.openai.com/codex/config-basic/).
- Highest to lowest documented configuration precedence: CLI flags/`--config`, trusted project files (closest to working directory wins), selected `--profile` file, user config, cloud-managed defaults, Unix `/etc/codex/config.toml`, built-in defaults. Project files are discovered from project root down to working directory and ignored for untrusted projects; user and system layers still load. Requirements are constraints, not ordinary defaults. [Configuration basics](https://developers.openai.com/codex/config-basic/), [advanced configuration](https://developers.openai.com/codex/config-advanced/).
- Do not infer that a file entry is effective just because it exists: other layers, project trust, and managed policy may alter or restrict the result. The published precedence is for configuration keys; it does not establish an independent whole-server replacement rule. [Configuration basics](https://developers.openai.com/codex/config-basic/).

## Registration fields

Each named table describes either a stdio server or a Streamable HTTP server. For stdio, `command` is required; optional `args`, `cwd`, `env`, and `env_vars` specify arguments, working directory, literal environment values and forwarded environment variables. `env_vars` supports names or `{ name, source }`; remote source requires remote MCP stdio. For HTTP, `url` is required; optional `auth`, `bearer_token_env_var`, `http_headers`, `env_http_headers`, and `http_headers_helper` control authentication and headers. `environment_id` defaults to `local` and can select a configured remote executor. [MCP guide](https://developers.openai.com/codex/mcp/), [configuration reference](https://developers.openai.com/codex/config-reference/).

Common controls include `enabled`, `required`, `startup_readiness`, `startup_timeout_sec` (default 10), `startup_timeout_ms` (alias), `tool_timeout_sec` (default 60), `enabled_tools`, `disabled_tools` (applied after allow list), `default_tools_approval_mode` and per-tool `tools.<tool>.approval_mode` and `output_token_limit`. `required = true` fails startup if an enabled server is not ready; `startup_readiness = "catalog"` permits a valid cached catalog, but tool calls still require a connection. Other advanced controls exist; consult the [full reference](https://developers.openai.com/codex/config-reference/) rather than assuming this list is exhaustive. [MCP guide](https://developers.openai.com/codex/mcp/).

## Credentials and modification constraints

- `bearer_token_env_var` and `env_http_headers` name environment variables rather than embedding their values; `env` and static `http_headers` can contain literal values, so configuration may itself contain secrets. `http_headers_helper` executes a local command, works only for locally connected HTTP, and its Authorization header loses to explicit bearer tokens and OAuth credentials. [MCP guide](https://developers.openai.com/codex/mcp/).
- OAuth is the default HTTP authentication fallback after configured bearer tokens and authorization headers; `auth = "chatgpt"` uses the current ChatGPT session only for the trusted first-party ChatGPT origin, with stored OAuth fallback. `codex mcp login <name>` initiates OAuth. `mcp_oauth_credentials_store` selects `auto`, `file`, or `keyring`. OAuth client settings include `oauth.client_id`, `oauth.client_secret`, `oauth.callback_url`, `oauth.callback_port`, `oauth_resource`, and `scopes`; a client secret is stored in configuration and requires a nonempty client ID. [MCP guide](https://developers.openai.com/codex/mcp/), [configuration reference](https://developers.openai.com/codex/config-reference/).
- Codex documents CLI `mcp add`, `list`, `get`, `remove`, `login`, and `logout`, and direct TOML editing. A writer should preserve unrelated TOML, unknown fields and credential-bearing values, avoid silently overwriting another registration, and not assume user-file modification overrides project/CLI or organizational policy. These are conservative integration recommendations, not guarantees of a Codex atomic editing API. No credential creation or server execution was performed. [MCP guide](https://developers.openai.com/codex/mcp/), [configuration basics](https://developers.openai.com/codex/config-basic/).
- Organization-managed requirements can constrain effective configuration separately from defaults; consult [admin-enforced requirements](https://developers.openai.com/codex/enterprise/managed-configuration/) for the applicable deployment. Project trust and remote execution also constrain whether a registration can run. Do not treat a local TOML edit as authority to bypass these controls. [Configuration basics](https://developers.openai.com/codex/config-basic/), [MCP guide](https://developers.openai.com/codex/mcp/).

## Open verification boundary

The official pages describe configuration and commands, not a stable third-party mutation API, cross-version conflict handling, transactional writes, or exact per-server table merging in every layer. Verify those against the targeted Codex release before implementing automatic modifications. Cloud/ChatGPT connectors and plugins have additional surface-specific behavior and are not equivalent to a local TOML registration. [MCP guide](https://developers.openai.com/codex/mcp/).
