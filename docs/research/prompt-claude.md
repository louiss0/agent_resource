# Claude Code prompts, skills, commands and agents

Research date: 2026-11-06. Scope: Anthropic's current online Claude Code documentation, retrieved on that date, not an immutable release specification. Its examples discuss features through at least v2.1.309; individual version gates below matter. This is **documented behavior**, not runtime verification: `claude` was not available on PATH in this environment, no authenticated Claude session was run, and no implementation source was examined. Online documentation may describe newer behavior than a deployed client. Pi-specific behavior is outside this Claude Code research; no Pi runtime equivalence is claimed. No product policy is chosen here.

## Skills and commands

Anthropic says [custom commands have been merged into skills](https://code.claude.com/docs/en/skills.md): `.claude/commands/deploy.md` and `.claude/skills/deploy/SKILL.md` both create `/deploy`; existing command files continue working. The older single-file command format accepts skill frontmatter except `name` and `paths`; the documentation prefers skills for new work because they also package supporting files. This is compatibility and a preference, **not a documented removal date**. Built-in fixed-logic commands and prompt-based bundled skills are not interchangeable categories. [Source: skills and commands](https://code.claude.com/docs/en/skills.md#choose-where-skills-load).

A skill is a directory with `SKILL.md`: YAML frontmatter and Markdown instructions. The directory or optional `name` determines the slash name; `description` guides automatic selection. A project skill lives at `.claude/skills/<name>/SKILL.md`, a personal skill at `~/.claude/skills/<name>/SKILL.md`, and a plugin skill at `<plugin>/skills/<name>/SKILL.md`, invoked as `/plugin-name:skill-name`. Enterprise managed locations, nested project locations, additional directories and account-synced skills have distinct discovery rules. Parent project directories are scanned to the repository root; nested skills below the starting directory are discovered when Claude works there. `--add-dir` loads that directory's `.claude/skills`, `.claude/commands`, and `.claude/agents`, unlike the access-only `permissions.additionalDirectories` setting. Cowork and cloud sessions do not read local personal skills. [Locations and caveats](https://code.claude.com/docs/en/skills.md#choose-where-skills-load).

### Invocation controls and package preservation

| Frontmatter | User slash invocation | Claude's Skill invocation | Context |
|---|---|---|---|
| Defaults | yes | yes | description advertised; full body on invocation |
| `disable-model-invocation: true` | yes | no | description not advertised; full body on user invocation |
| `user-invocable: false` | no | yes | description advertised; full body on invocation |

Thus **yes**: set `disable-model-invocation: true` on the existing `SKILL.md` and retain its directory, references, and scripts; do not set `user-invocable: false` if direct slash invocation is required. This also prevents preloading into subagents and running as the prompt of a session-scoped scheduled task. It controls the Skill mechanism, not a guarantee that a model could never independently reproduce similar steps. The docs say Claude Code blocks an attempted invocation and instructs Claude not to reproduce the steps another way. [Invocation table](https://code.claude.com/docs/en/skills.md#control-who-invokes-a-skill), [frontmatter](https://code.claude.com/docs/en/skills.md#frontmatter-reference).

A slash at the beginning of a message invokes directly; a standalone slash name after ordinary prose grants permission for that message but does not itself directly invoke. `skillOverrides` settings and Skill permission rules supply additional controls; policy, disabled tools and discovery still affect availability. [Invocation](https://code.claude.com/docs/en/skills.md#control-who-invokes-a-skill), [permissions and overrides](https://code.claude.com/docs/en/skills.md#restrict-claudes-skill-access).

### Arguments, model and assets

`argument-hint` is an autocomplete hint, not an argument schema. `$ARGUMENTS` expands to the complete supplied string; `$ARGUMENTS[N]` and `$N` select zero-based, shell-quoted positional arguments; `arguments` declares named positions used as `$name`. Missing indexed placeholders remain literal, whereas missing named ones become empty. If no placeholder receives an argument, Claude Code appends `ARGUMENTS: <value>`. Substituted argument text is not re-expanded as argument placeholders. Interactive terminal sessions can stack skills at the start of a message; `claude -p` and Agent SDK load only the first and treat the rest as arguments. [Substitutions](https://code.claude.com/docs/en/skills.md#available-string-substitutions), [stacking](https://code.claude.com/docs/en/skills.md#stack-several-skills-in-one-message).

Skill `model` overrides the active model for the rest of the current turn, not permanently; `inherit` retains it. Organizational model allowlists and certain permission modes can prevent the requested override. With `context: fork`, the model applies to the forked subagent instead. `effort` likewise applies for the turn or fork, subject to the documented environment override. `allowed-tools` preapproves tools for the invoking turn rather than restricting the tool pool; `disallowed-tools` removes tools for that turn. Exact fields matter: unknown frontmatter keys are silently ignored, and invalid YAML causes loading without fields. [Field reference](https://code.claude.com/docs/en/skills.md#frontmatter-reference).

A skill can retain adjacent Markdown references, examples and executable scripts, which its body should explicitly reference. `${CLAUDE_SKILL_DIR}` locates the installed skill directory; `${CLAUDE_PLUGIN_ROOT}` is available for plugin content. Backtick shell injection `!` followed by a backtick command runs before sending the rendered skill to the model, subject to settings and client restrictions; it is not simply an instruction to the model. [Assets](https://code.claude.com/docs/en/skills.md#add-supporting-files), [substitutions](https://code.claude.com/docs/en/skills.md#available-string-substitutions), [dynamic injection](https://code.claude.com/docs/en/skills.md#inject-dynamic-context).

### Collision and plugin rules

For same-named skills, enterprise beats personal beats project; a skill beats an old command file. Plugin skills are namespaced and coexist. Project-root and nested skills can coexist with qualified nested names. Added directories have their own qualified collision handling, documented as requiring v2.1.309 or later. Local skills can replace bundled skills or built-in commands by name without replacing their aliases. These are Claude Code rules, not generic Agent Skills guarantees. [Precedence](https://code.claude.com/docs/en/skills.md#resolve-skills-that-share-a-name).

The [plugin manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference.md#fields) documents default `skills/`, `commands/`, and `agents/` directories. Manifest `skills` paths add to the default skills scan; `commands` and `agents` paths replace their respective default scans. A plugin command object can provide `source` or inline `content`, with `description`, `argumentHint`, `model`, and `allowedTools`. Component paths must exist inside the plugin root and generally start `./`. A plugin's Markdown content can interpolate `${CLAUDE_PLUGIN_ROOT}`; the installed plugin root can change on updates. [Manifest paths](https://code.claude.com/docs/en/plugins/manifest-reference.md#path-rules), [variables](https://code.claude.com/docs/en/plugins/manifest-reference.md#environment-variables).

## Native Claude Code subagent implications

Subagents are a different primitive, not merely another spelling of a skill. File-based agents use YAML frontmatter followed by a **system prompt** in Markdown; the separate delegation message provides the task. `name` and `description` are required for ordinary project/user files. Project `.claude/agents/`, personal `~/.claude/agents/`, plugin `agents/`, managed definitions and session `--agents` have separate precedence: managed, CLI, project, user, plugin. Project and personal directories are recursive; plugin subdirectories contribute to the scoped identifier. Same-name files within one ordinary agent tree have filesystem-read-order rather than guaranteed precedence. [Agent scope and format](https://code.claude.com/docs/en/sub-agents.md#choose-the-subagent-scope).

For a skill with `context: fork`, the selected agent's system prompt configures the environment and the rendered skill body is the **task prompt**; the fork does not inherit conversation history. Conversely, an agent's `skills` field preloads full skill bodies into its context at startup while Claude's delegation message provides the task. `disable-model-invocation: true` prevents such preloading. Thus moving a skill body into an agent body changes its role; retaining the skill alongside an agent is also documented. [Interaction table](https://code.claude.com/docs/en/skills.md#run-skills-in-a-subagent), [agent fields](https://code.claude.com/docs/en/sub-agents.md#supported-frontmatter-fields).

Skill `$ARGUMENTS`, positional and named substitutions are documented for skill content; the agent documentation instead describes the agent Markdown as a system prompt and delegation messages as tasks. It does not establish an equivalent automatic slash-template argument substitution for agent bodies. Do not assume one without a version-specific test or further first-party evidence. Agent `skills` can preload packaged references, subject to invocation controls; an agent file itself is not documented as a skill-directory package. Plugin `${CLAUDE_PLUGIN_ROOT}` is explicitly substituted in agent Markdown content, so plugin-distributed agents can refer to plugin assets. [Agent definition](https://code.claude.com/docs/en/sub-agents.md#write-subagent-files), [plugin content substitution](https://code.claude.com/docs/en/plugins/manifest-reference.md#where-each-variable-resolves).

Agent `model` supports family aliases, full IDs and `inherit`. Documented resolution is per-invocation Agent tool model, agent frontmatter, `CLAUDE_CODE_SUBAGENT_MODEL`, then main conversation model, subject to model restrictions and special cases. Before v2.1.251 the environment variable had higher priority. Agent `tools` and `disallowedTools` differ from skill `allowed-tools`; plugin agents ignore `hooks`, `mcpServers` and `permissionMode`. [Agent model order](https://code.claude.com/docs/en/sub-agents.md#choose-a-model), [agent fields and plugin limitations](https://code.claude.com/docs/en/sub-agents.md#choose-the-subagent-scope).

## Verification boundaries

No claims above are measured runtime results. In particular, test actual client version, user versus headless invocation, conflicts, manual-only preloading, argument escaping, model allowlists and asset paths in the target deployment before relying on them. The documentation is live and may change; version-specific caveats above are non-exhaustive. Claude Code behavior does not establish Claude API, Claude Desktop, Cowork, or Pi behavior beyond the explicit scope noted in the cited docs.
