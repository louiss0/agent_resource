# Codex prompt, skill, and agent semantics

Research baseline: 2026-11-06. OpenAI's live documentation for current local Codex clients, not a tested installed Codex release; redirects and schemas may change. This is evidence for later decisions, not a conversion policy. OpenAI documentation links below are first-party and were retrieved as Markdown. Web search tooling was unavailable; direct first-party HTTP and GitHub issue search were used instead.

## Instructions and manual resources

* [`AGENTS.md`](https://developers.openai.com/codex/guides/agents-md.md) is automatically loaded guidance, not an explicitly invoked prompt. Codex loads the first nonempty `AGENTS.override.md` or `AGENTS.md` in `$CODEX_HOME` (default `~/.codex`), then at most one per directory from project root to CWD, with nearer instructions later; configurable fallback names and a default 32 KiB combined limit apply. The [original Codex guide URL](https://developers.openai.com/codex/guides/agents-md.md) supplied this evidence.
* [Custom prompts](https://learn.chatgpt.com/docs/custom-prompts) are **deprecated**, but documented for CLI and IDE. Top-level Markdown files in `$CODEX_HOME/prompts/` (normally `~/.codex/prompts/`) become explicitly invoked `/prompts:<filename>` commands. They are user-home resources, not repository-shared native prompts; subdirectories and non-Markdown files are ignored. Restart or open a new chat to load edits. YAML `description` and `argument-hint` describe completion; the Markdown body expands into a message. `$1`â€“`$9` are positional, `$ARGUMENTS` is the whole argument string, uppercase `$NAME` placeholders accept `NAME=value`, quoted values can contain spaces, and `$$` emits a literal dollar sign. These are text substitution semantics, not an agent or model selection mechanism in the documented prompt schema.
* [Skills](https://learn.chatgpt.com/docs/build-skills) are the current reusable workflow form. A directory contains `SKILL.md` with required `name`, `description`, and instructions, with optional `scripts/`, `references/`, `assets/`, and `agents/openai.yaml`. CLI and IDE allow `/skills` or `$skill` explicit selection; normally the model may also select based on description. Codex initially sees metadata and path and reads the full instructions on selection; support files are distinct resources. The docs do not specify the custom-prompt placeholder syntax as skill argument substitution.
* Repository skills are discovered in `.agents/skills` from CWD through the Git root; user skills are in `$HOME/.agents/skills`, admin skills in `/etc/codex/skills`, and system skills are bundled. Symlinks are followed. A project can share skills; these locations differ from `$CODEX_HOME/prompts`. Same-name skills do not merge. See [locations and invocation](https://learn.chatgpt.com/docs/build-skills#where-to-save-skills).
* In `agents/openai.yaml`, `policy.allow_implicit_invocation: false` disables implicit selection while retaining explicit `$skill` invocation; its default is true. The same sidecar may provide presentation metadata, `default_prompt`, and MCP tool dependencies. This is different from disabling a skill outright with `[[skills.config]]` in Codex config. Source: [optional metadata and configuration](https://learn.chatgpt.com/docs/build-skills#optional-metadata).

## Native agent definitions and conversion-relevant distinctions

[OpenAI's subagent documentation](https://learn.chatgpt.com/docs/subagents#custom-agents) describes project `.codex/agents/*.toml` and user `~/.codex/agents/*.toml` standalone custom agents, each requiring `name`, `description`, and `developer_instructions`. Agents are spawned/delegated rather than expanded into the caller's user message. They can set `model` and `model_reasoning_effort`; an agent-file value takes precedence over the previously resolved explicit spawn, `[agents]` default, and parent setting. If a file changes only model it preserves the previously resolved effort; model compatibility therefore matters. Agents inherit parent permissions, provider, MCP servers, and skills; their configuration can disable individual skills and supported capabilities but cannot replace sandbox or approval policy. Consult the linked schema for the current supported fields.

Consequently an instruction body, a prompt expanded with call-time placeholders, a skill and its sidecar/supporting files, and a spawned agent with its own model settings are not interchangeable representations. The cited agent schema does not document prompt-style placeholder expansion or automatic bundling of a skill's adjacent assets into an agent definition. Preserve these distinctions for a future decision; no conversion behavior is prescribed here.
