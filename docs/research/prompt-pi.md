# Pi prompt templates, skills, presets, and agent definitions

**Research date:** 2026-11-06. **Baseline:** first-party `@earendil-works/pi-coding-agent` 1.5.0 installed docs and examples, checked against upstream [commit 6bf2ab9bbb64fd14793e506a5404078441219b95](https://github.com/earendil-works/pi/tree/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent), whose package also declares 1.5.0. The linked upstream commit is the precise documentary baseline, not a claim that the installed distribution is byte-identical: some upstream files changed without a package version change. This is source/documentation research, not runtime verification. Web research tools were unavailable; first-party GitHub content was accessed via `gh api`. The findings do not select product policy.

## Core prompt templates

A template is a Markdown file exposed as `/<filename-without-extension>`; optional YAML `description` appears in completion (otherwise first nonempty line), and `argument-hint` describes arguments using `<required>` and `[optional]`. The documentation calls this a hint, not validation. Pi expands the template before text enters the agent; extensions first receive raw input via `input` unless a same-named extension command handles it. `/reload` reloads changes. [Prompt templates](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/prompt-templates.md)

Template substitution supports `$1`, `$2`, etc.; `$@` and `$ARGUMENTS` for all arguments; `${1:-default}` and `${@:-default}`; `${@:N}` and `${@:N:L}` for slices. Arguments use shell-like quoting, with specific edge-case rules in the linked documentation. This is text expansion, not a per-template model override or executable preset. The documented frontmatter is description and hint, not a model or asset declaration. [Prompt templates](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/prompt-templates.md)

## Core skills and the manual-only comparison

Skills are directories with `SKILL.md`, optionally accompanied by scripts, references, and assets; references should be relative to the skill directory. Pi normally advertises name, description and path in the system prompt and the model reads instructions when appropriate. `/skill:name` explicitly loads instructions; trailing arguments are appended as a user request, not substituted into numbered placeholders. `disable-model-invocation: true` hides the skill from automatic model selection while preserving explicit invocation. `enableSkillCommands` defaults to true and controls interactive discovery; the skills documentation explicitly says manually typed `/skill:name` still works when disabled. A model can fail to load a relevant skill automatically. [Skills](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/skills.md); [settings](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/settings.md#resources).

A manual-only skill-backed resource is thus **not equivalent** to a native template: its explicit command is namespaced, it loads a skill body and appends a request, and it has a skill-directory asset convention; a template expands its own positional expressions into a user prompt. The skill flag controls automatic selection rather than serving as an access-control boundary: explicit commands and other ways of reading a file remain possible. Neither representation documented here inherently configures a model. A standalone template can mention files, but no automatic skill-relative asset packaging or equivalent binding is documented. [Skills](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/skills.md); [templates](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/prompt-templates.md).

Skill frontmatter also documents name, description, license, compatibility, metadata and experimental `allowed-tools`; do not infer that `allowed-tools` grants or enforces runtime permissions. Missing descriptions and malformed files prevent loading; collisions retain the first discovered skill with a warning. [Skills](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/skills.md)

## Locations and distribution

The agent directory defaults to `~/.pi/agent` and can be overridden by `PI_CODING_AGENT_DIR` or the SDK. User templates and skills conventionally live in its `prompts/` and `skills/`; project counterparts are `.pi/prompts/` and `.pi/skills/`. Pi also discovers `~/.agents/skills/` and project `.agents/skills/` from cwd through ancestors up to the repository root. Skill directories containing `SKILL.md` are recursively discovered; conventional prompt directories discover only direct `.md` children. Project `.pi` resources require project trust. [Configuration](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/configuration.md); [skills](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/skills.md); [templates](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/prompt-templates.md); [security](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/security.md#understand-project-trust).

Settings can explicitly select skill and prompt paths; user paths resolve from the agent directory and project paths from project `.pi`, and resource arrays combine. Packages from npm, git or local paths can distribute `skills/`, `prompts/`, extensions and themes, or select other paths/globs via `package.json`'s `pi` manifest; per-package filters narrow rather than expand the manifest. Project package declarations are trust-gated. Nested prompt files may be selected via settings or package manifest even though conventional discovery is shallow. [Settings](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/settings.md#resources); [packages](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/packages.md).

## Models and extension presets

Core provides `/model`, `/thinking`, startup defaults, CLI selection, and model cycling; these are session/startup controls, not documented template frontmatter. [Slash commands](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/slash-commands.md); [model settings](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/settings.md#model-and-thinking).

The first-party **example extension** [`preset.ts`](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/examples/extensions/preset.ts) adds `--preset`, `/preset` and cycling, and reads user `presets.json` plus cwd `.pi/presets.json` with project names overriding user names. It can set provider/model, thinking, active tools, and system-prompt instructions; its code warns if the model is missing or credentials fail. This example must be installed/loaded for those commands and JSON semantics; it is not native prompt-template metadata. Its project file is read by extension code, so do not assume core resource trust rules apply to that custom read. Separately, core supports virtual models registered by an extension (or SDK), which route requests to physical model/thinking pairs; that is routing, not a prompt template. [Virtual models](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/docs/virtual-models.md).

## Agent-definition conversion evidence, not a conversion policy

Pi core documentation here does not define a universal built-in agent-definition format. The first-party [subagent example extension](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/examples/extensions/subagent/README.md) provides one particular format and must be installed for its semantics. It launches a separate Pi process per subagent. Its Markdown definitions have required `name` and `description`, optional `tools` and `model`, and an instruction body. User `~/.pi/agent/agents/*.md` is the default scope; project `.pi/agents/*.md` requires explicit project or both scope, and project entries override user names when combined. Project trust/confirmation conditions are extension-specific. The [discovery implementation](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/examples/extensions/subagent/agents.ts) shows the supported fields and nearest project directory search.

The [extension implementation](https://github.com/earendil-works/pi/blob/6bf2ab9bbb64fd14793e506a5404078441219b95/packages/coding-agent/examples/extensions/subagent/index.ts) sends the body through a temporary file as `--append-system-prompt`, and sends `Task: ...` separately. It passes a specified model as `--model` and tools as `--tools`; absent a model, it passes the dispatching model and thinking level. It does not implement template `$1`/`$ARGUMENTS` substitutions in the definition body; chain task `{previous}` is a different feature. Moving a template body therefore changes its role from expanded user prompt to appended system instructions and does not by itself preserve arguments. A skill's relative support assets likewise have no documented agent-definition asset field or automatic relocation/path rebasing in this example. The model, tools, instruction context, task and support files all require explicit consideration; no lossless conversion is established.

These statements are scoped to the cited example, not every third-party or locally installed subagent implementation. No runtime test established loading, invocation, model behavior, support-file resolution, or equivalence; a product decision would need to select a target extension and address these uncertainties separately.
